# Проверки восьмого дня

Среда: Windows, Node.js 24.22.3, Nuxt 4.6.4, PostgreSQL 18.7, Chrome. Рабочая база — `workflow_day8`; тесты используют отдельные временные SQL-схемы.

## Состав проверок

- 35 unit/integration-тестов: сохранены 27 прежних, добавлены восемь проверок SLA, эскалации и файлов.
- 21 E2E-сценарий: сохранены 17 прежних, добавлены четыре пользовательских сценария восьмого дня.
- Typecheck проверяет приложение и TypeScript тестов. ESLint допускает ноль предупреждений.
- Production-сборка сохраняет предрендеринг пяти публичных страниц.
- Автоматическая проверка архитектуры проверяет границы и циклы.

Фактический итог полного прогона находится в `verification-result.json`. Подробные локальные отчёты и снимки — в `.verification/day8`.

## База и API

Проверяется чистая установка и обновление старой схемы с сохранённой заявкой. Миграция запускается повторно; история содержит одну применённую версию. Заявка сохраняется, поля SLA заполняются, SQL constraint запрещает эскалацию без причины.

Реальный HTTP-прогон проверяет четыре роли, настройки всех приоритетов, валидацию сроков, применение SLA к созданию и смене приоритета, обязательную причину и новое состояние заявки.

Проверяются собственные уведомления, отсутствие чужих, невозможность пометить чужое сообщение, отметка своего и отсутствие повторного предупреждения SLA.

Для файлов проверяются настоящий размер, подпись содержимого, лимит количества, закрытая заявка, чужая заявка и анонимный доступ. Две параллельные загрузки по три файла дают один успех и один отказ; в БД остаётся три файла. Скачанные байты сравниваются с исходным PNG.

Аналитика сверяется после добавления и эскалации заявки: растут общий счётчик, нужный статус и загрузка исполнителя. Отдельно проверяется серверный запрет для остальных ролей.

## Браузер и макет

Новые E2E проверяют сохранение SLA, pending, HTTP 500 и повтор, refresh, пустую и заполненную причину эскалации, уведомление, ошибки размера/типа/количества, повтор upload после 500, скачивание и сохранение файла после refresh.

SLA, уведомления и аналитика снимаются на 360, 768 и 1280 px. Проверяется отсутствие горизонтального переполнения. Состояния сопоставлены с 20 экспортами Figma восьмого уровня.

Сохранены сценарии старых дней: login → create → assign → status → comment → logout, гонки поиска и сессии, дубли комментария, URL и черновики после refresh, HTTP 401/409/500, SSR, metadata, 404 и hydration.

В старом тесте Undo возвращение к CRM после обзора теперь проходит через общий список. Новые seed-заявки заняли места в трёх последних заявках обзора. Перед выбором приоритета тест ждёт заголовок деталей: иначе такой же select ещё виден в фильтрах предыдущей страницы. Проверки Undo в PostgreSQL и отдельного закрытия уведомления сохранены; тест больше не предполагает, что конкретная заявка всегда входит в первые три.

## Найденные при разработке ошибки

После добавления расчёта реакции старый HTTP-сценарий назначения получил 500: PostgreSQL не мог определить тип nullable-параметра в CASE. Добавлен явный `::text`; тот же старый сценарий и новые HTTP-проверки повторены.

Сообщение о пустой причине эскалации оставалось после заполнения поля. Теперь ошибка формы снимается при вводе причины; сервер всё равно проверяет её независимо.

## Изоляция и материалы

Тестовый сервер — 3108. Перед каждым E2E загружаются fixtures, браузерный контекст чистый. SLA timer отключён только для тестов; проверки выполняются явно. SQL-схемы удаляются после завершения, рабочие заявки не используются.

Проверки ошибок используют управляемые ответы и Promise, без произвольного sleep и автоматического повтора упавшего теста. Снимки результатов — представление фактического JSON-отчёта, не имитация консоли.

Архив содержит исходники, миграцию, seed, тесты, документацию и макет. `.env`, пароли подключения, зависимости, временные сборки и документы других учебных работ исключаются.
